# PRD: 개발자 프로필 웹사이트 (DemoPort)

## 1. 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | DemoPort |
| 목적 | 개발자 개인 프로필과 프로젝트를 소개하는 포트폴리오 웹사이트 |
| 개발자 | 최종현 |
| 이메일 | dedman0802@gmail.com |
| 주 개발 분야 | 바이브코딩, Python, HTML5 |
| 문서 상태 | 초안 (v0.1) |

### 1.1 배경
개발자를 소개하는 자료가 흩어져 있으면 채용 담당자나 협업 제안자가 역량을 한눈에 파악하기 어렵다. 하나의 웹사이트에서 자기소개, 기술 스택, 프로젝트, 연락처를 보여주어 첫인상과 신뢰도를 높인다.

### 1.2 목표
- 방문자가 1분 안에 "누구이고, 무엇을 잘하며, 어떻게 연락하는지" 파악할 수 있다.
- 바이브코딩, Python, HTML5 역량을 실제 프로젝트(데모)로 보여준다.
- 별도 서버 없이 정적 호스팅(GitHub Pages 등)으로 배포할 수 있다.

### 1.3 비목표 (이번 범위 제외)
- 회원가입/로그인, 관리자 페이지
- 블로그 CMS, 댓글 기능
- 서버 사이드 데이터베이스

## 2. 타깃 사용자

| 사용자 | 필요 |
|--------|------|
| 채용 담당자 | 기술 스택과 대표 프로젝트를 빠르게 확인하고 연락하고 싶다 |
| 협업/외주 제안자 | 어떤 종류의 작업이 가능한지 알고 싶다 |
| 동료 개발자 | 결과물과 작업 방식(바이브코딩)이 궁금하다 |

## 3. 핵심 콘텐츠와 기능 요구사항

### 3.1 페이지 구성 (싱글 페이지, 섹션 스크롤)

| 순서 | 섹션 | 내용 |
|------|------|------|
| 1 | 헤더/내비게이션 | 로고(이름), 섹션 이동 링크, 상단 고정 |
| 2 | 히어로 | 이름(최종현), 한 줄 소개, 주 개발 분야, 연락하기 버튼 |
| 3 | 소개 (About) | 개발자 소개, 바이브코딩을 활용한 개발 방식 |
| 4 | 기술 스택 (Skills) | 바이브코딩, Python, HTML5 및 연관 기술 |
| 5 | 프로젝트 (Projects) | 프로젝트 카드 목록 (제목, 설명, 사용 기술, 데모/소스 링크) |
| 6 | 연락처 (Contact) | 이메일 주소, 메일 보내기 버튼 |
| 7 | 푸터 | 저작권, 맨 위로 이동 |

### 3.2 기능 요구사항

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-01 | 내비게이션 클릭 시 해당 섹션으로 부드럽게 스크롤한다 | 필수 |
| F-02 | 히어로 섹션에 이름, 소개 문구, 주 개발 분야를 표시한다 | 필수 |
| F-03 | 기술 스택을 카테고리(바이브코딩 / Python / HTML5)별로 표시한다 | 필수 |
| F-04 | 프로젝트를 카드 형태로 보여주고 각 카드에 데모/소스 링크를 제공한다 | 필수 |
| F-05 | 이메일(dedman0802@gmail.com)을 `mailto:` 링크로 제공한다 | 필수 |
| F-06 | 이메일 주소 복사 버튼을 제공한다 | 선택 |
| F-07 | 라이트/다크 테마 전환을 지원한다 | 선택 |
| F-08 | 스크롤 시 섹션이 나타나는 가벼운 애니메이션을 적용한다 | 선택 |

프로젝트 목록 데이터는 HTML을 직접 고치지 않고 수정할 수 있도록 별도 데이터 파일(JSON 또는 JS 객체)로 분리한다.

### 3.3 초기 프로젝트 후보
이미 만든 결과물을 데모로 연결할 수 있다.

| 프로젝트 | 기술 | 비고 |
|----------|------|------|
| 테트리스 | HTML5, CSS3, JavaScript | 브라우저에서 바로 실행되는 데모 |
| 뱀게임 | Python (tkinter) | 소스 링크와 스크린샷으로 소개 |

## 4. 비기능 요구사항

| 구분 | 요구사항 |
|------|----------|
| 반응형 | 모바일(360px)부터 데스크톱(1440px)까지 레이아웃이 깨지지 않는다 |
| 성능 | 초기 로딩이 빠르도록 외부 라이브러리를 최소화한다 (목표: Lighthouse 성능 90점 이상) |
| 접근성 | 시맨틱 태그 사용, 이미지 대체 텍스트, 충분한 색 대비, 키보드 탐색 가능 |
| 호환성 | 최신 Chrome, Edge, Safari, Firefox |
| SEO | title, meta description, Open Graph 태그 설정 |
| 유지보수 | HTML/CSS/JS 파일 분리, 프로젝트 데이터 분리 |
| 개인정보 | 이메일 외 개인정보(전화번호, 주소)는 게시하지 않는다 |

## 5. 기술 스택

| 영역 | 선택 | 이유 |
|------|------|------|
| 마크업 | HTML5 (시맨틱 태그) | 주 개발 분야이며 정적 배포에 적합 |
| 스타일 | CSS3 (변수, Flexbox/Grid, 미디어 쿼리) | 프레임워크 없이 가볍게 구현 |
| 동작 | Vanilla JavaScript | 스크롤, 테마 전환, 데이터 렌더링 |
| 개발 방식 | 바이브코딩 (AI와 대화하며 개발) | 개발자의 주 분야를 사이트 제작 과정에서도 보여줌 |
| 보조 도구 | Python | 로컬 미리보기 서버(`python -m http.server`) 등 |
| 배포 | GitHub Pages 또는 Netlify | 무료 정적 호스팅 |

## 6. 디자인 방향
- 분위기: 깔끔하고 현대적인 개발자 포트폴리오, 코드/터미널 느낌의 포인트 요소
- 색상: 다크 배경 기반에 강조색 1개 (라이트 테마도 지원)
- 서체: 한글 가독성이 좋은 산세리프 + 코드용 고정폭 서체
- 레이아웃: 중앙 정렬 컨테이너(최대 폭 1100px 내외), 넉넉한 여백

## 9. 성공 지표
- 핵심 섹션(소개, 기술 스택, 프로젝트, 연락처)이 모두 구현되어 있다.
- 모바일과 데스크톱에서 레이아웃이 정상적으로 보인다.
- Lighthouse 성능, 접근성, SEO 점수가 각각 90점 이상이다.
- 이메일 링크와 프로젝트 데모 링크가 모두 정상 동작한다.

- 프로젝트 데모를 사이트에 직접 포함할 것인가, 외부 링크로 연결할 것인가?
